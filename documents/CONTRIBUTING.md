# Contributing

Thanks for your interest in contributing to this project! This guide explains the recommended workflow and expectations for contributors.

Getting started

1. Fork the repository and create a topic branch (e.g., `docs/add-setup`, `feature/catalog-filter`).
2. Make small, focused commits and push your branch to your fork.
3. Open a Pull Request (PR) describing the change and linking any relevant issues.

Branch naming

- Use `feature/`, `bugfix/`, `docs/`, or `hotfix/` prefixes for branches.

Commit messages

- Follow a short, clear style: `docs: add SETUP.md` or `fix: correct typo in CatalogController`.

Code style

- Respect the existing project layout and C# coding conventions. If you use an analyzer or formatter, prefer the project's settings.

Pull request checklist

- [ ] The PR is limited to a single purpose
- [ ] Code builds locally and passes smoke tests
- [ ] Documentation updated when public APIs change
- [ ] Describe testing steps and expected behavior in the PR description

Reporting issues and security

- Open an issue for bugs or enhancements. For sensitive security issues, contact repository maintainers directly (create an issue marked private or use a provided security contact).

Maintainers

- Maintainers will review PRs and provide feedback. Expect at least one approving review before merging.
